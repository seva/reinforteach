## Learnings

- **Gateway Config Stripping:** The OpenClaw gateway strips unknown fields from agent configurations upon reload. The plugin configuration must reside in `plugins.entries.reinforteach.config` and be accessed via `api.pluginConfig`.
- **Hugging Face Model ID Requirement:** Unsloth's `FastLanguageModel.from_pretrained` requires a Hugging Face repository ID (e.g., `unsloth/Qwen3.5-9B`) to pull unquantized weights; passing the path to the `.gguf` file directly causes a runtime error. Added mapping logic to `dpo_runner.py`.
- **Llama.cpp Python Windows Compatibility:** `llama-cpp-python` dropped pre-built Windows wheels after version v0.3.4. Pre-built v0.3.4 cu124 wheels are backward-compatible with CUDA 12.6+ without requiring an MSVC compiler.
- **Subagent Session Filtering:** `getSessions` must filter out subagent sessions (`spawnedBy` exists) from the session store, otherwise attribution might match against internal reasoning turns.

## Risks

- **Unsloth Memory Usage:** Training a 9B model on an 8GB VRAM GPU with 4-bit quantization will be tight during the backpropagation step. Out-of-memory (OOM) errors remain a risk during the first actual training run.
- **Buffer Quality:** Operator feedback might cluster around a single failure mode. A low-diversity buffer might overfit the model before significant improvement occurs.

## Strategy

- **Operational Execution:** Await 10 real operator negative feedback messages to fill the `training_buffer.jsonl` and trigger the automated training loop via the scheduler.
- **Monitor the First Run:** Pay close attention to the first execution of `train_and_deploy.py` to verify that Unsloth successfully completes training and the deployment gate correctly measures the model shift.

## Decisions

- **Oracle Configuration:** Elected to use `opencode-cli/anthropic/claude-opus-4-6` (as the `guru` agent) for the oracle, ensuring a substantial capability gap over the local Qwen3.5-9B model for generating chosen completions, at no additional API cost under the existing Claude subscription.
- **Setup Automation:** Selected a deterministic, idempotent, parameterized `.pseudo` file (`docs/setup.pseudo`) for environment setup over a complex Python or Bash installation script, due to the nuances of the CUDA version matrix.

## Alignment

- **Test-Driven Rigor Reinforced:** A TDD violation occurred when writing implementation code without an accompanying test. Reverted code to ensure a test task was added to `IMPLEMENTATION.md` and the test was written before the implementation.
- **Constitutional Truth:** Purged `ARCHITECTURE.md` of line-level implementation noise (coverage notes). Ensure architecture documents describe structural and interface invariants, not transient point-in-time metrics.

## Tradeoffs

- **Oracle Subprocess Overhead:** Accepted the minor latency of using `opencode-cli` to spawn the `guru` oracle, because the throughput (3–14 calls/day) makes the overhead irrelevant compared to the ease of reusing the existing Claude subscription.

## Alternatives

- **Using the Grok Agent for Oracle:** Considered using the `grok` agent (qwen3.5-flash) but rejected it due to its lower capability ceiling compared to the model being trained (Qwen3.5-9B). The oracle must be strictly higher-capability to generate meaningful DPO pairs.
